# 案例：一次"只改注释"的批量改动烧掉 949 万 token

2026-11，一个仓库要把全部注释与 docstring 翻成中文。主 Agent 把 11 个文件交给一个子 Agent（`Translate core query comments`），要求它"逐处修改并逐文件校验"。结果：

| 指标 | 数值 |
|---|---|
| 文件 / 行数 | 11 / 2,638 |
| 译文总量 | 约 40,478 字符（≈2.5 万 token 输出） |
| 轮次（模型调用） | 106 |
| 工具调用 | 328（`edit` 282、`bash` 32、`read` 13、`grep` 1） |
| 合计 token | 9,488,463 |
| 其中缓存读取 | 9,312,512 |
| 新输入 / 输出 | 82,726 / 93,225 |
| 末轮上下文 | 168,832 |
| 平均每轮 | 89,514 |
| 平均每次 `edit` | 33,600 |
| 平均每源码行 | 3,600 |

## 钱花在哪

按轮次类型拆：

| 类型 | 轮次 | token | 占比 |
|---|---|---|---|
| 只有 `edit` 的轮次 | 62 | 4,734,095 | 50% |
| 读文件 / 跑校验的轮次 | 42 | 4,484,950 | 47% |

58 个轮次只发了 1 个工具调用 —— 一轮一处 `edit`，每轮都把 10 万级上下文重发一次。另有 32 次逐文件跑校验脚本（`bash`），每次都在更大的上下文里跑。

按文件拆，越靠后的文件越贵（同样的改动，上下文翻倍）：

| 文件 | `edit` 次数 | token |
|---|---|---|
| `hybrid_search.py` | 55 | 1.03M |
| `response_builder.py` | 31 | 0.56M |
| `query_processor.py` | 43 | 0.55M |
| `sparse_retriever.py` | 23 | 0.51M |
| `reranker.py` | 28 | 0.46M |
| `dense_retriever.py` | 17 | 0.44M |
| `multimodal_assembler.py` | 42 | 0.42M |
| `fusion.py` | 25 | 0.41M |
| `citation_generator.py` | 16 | 0.32M |

## 对照实验

同一时期另一个子 Agent（`translate-tests-integration`）改了更多文件，只花 41 轮 / 404 万 token，原因是它**一轮并发 20 个 `edit`**（802 次工具调用 / 41 轮）。同样的工作量，轮次差 2.6 倍、token 差 2.3 倍。

结论：**决定成本的是每轮的批处理量，不是任务大小。**

## 同样的产出，别的方式要多少

| 方式 | 轮次 | token |
|---|---|---|
| 逐处 `edit` + 每文件校验（实际发生） | 106 | 9.49M |
| 批量 `edit`（每轮 10 个） | 35～40 | 3～4M |
| 每文件一次 `write` 整文件重写 | 20～25 | 1～1.5M |
| 脚本替换 + 一次校验 | 10～15 | 0.5～0.8M |
| 理论下限（2.5 万 token 输出 ÷ 单轮上限） | 7～8 | 0.3～0.4M |

## 六条教训

1. **成本 ≈ 轮次 × 上下文**，而上下文只增不减。改写量除以单轮输出上限，就是物理下限；超过下限 3 倍一定是方式错了。
2. **一个文件一轮一个 `edit` 是最贵的模式**：每处改动都要重发整个历史，几百处就是几十万 token 的重复输入。
3. **校验要一次性做**，不是每文件做。逐文件跑脚本把"读文件/跑命令"的轮次从 0 涨到 42 轮、448 万 token。
4. **改完不要回读**。回读只是把已经在上下文里的内容再买一遍；用校验脚本一次性证明。
5. **高改动密度的文件（>20 处）应该整文件重写**，而不是逐条替换。11 个文件里有 5 个在 25 处以上。
6. **委派要写死执行方式**。子 Agent 会忠实复刻指令里的做法：说"逐处修改、逐文件校验"，它就会跑 106 轮，而且它不会自己意识到贵 —— 预算约束必须写进委派指令。

## 当时用的校验脚本证明了什么

改动完成后，195 个文件的校验结果是 193 个 `.py` 全部通过（27 个提示 docstring 并行，内容无损）、2 个配置样例通过。校验项是：去掉 docstring 的 AST 一致、docstring 数量一致、非 docstring 字符串一致、指令注释原样、行尾不变。

也就是说：**成本高不等于质量高**。949 万 token 换来的是 195 个文件的正确改动；同样的正确性，脚本 + 一次性校验用 1/10 的成本就能拿到。
