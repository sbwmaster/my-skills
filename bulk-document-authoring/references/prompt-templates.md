# 提示词模板

以下模板假设输出中文。换成其他语言时只改语言那一行，规则不变。

## 章节单元（一次性成稿，默认用法）

```
你是<领域>的专业撰写人。请撰写《<书名>》第 <N> 章「<标题>」的完整正文，中文 Markdown。

## 本章覆盖内容
<3～6 个具体主题，逗号分隔，每个主题带 2～5 个关键词>

## 边界
不要写：<相邻章的 2～3 个主题>。相邻章节由他人撰写，不要越界。

## 格式
- 第一行必须是 `## 第 <N> 章 <标题>`，只输出本章正文，不写书名、目录、导语、"本章完"。
- 用 `### <N>.1 ...`、`#### ...` 分级；至少 1 个表格、2 个编号流程、若干列表；不要用代码块、图片、外链。

## 篇幅
- 正文约 <6,000> 个汉字。一次写足，不要提前收尾。

## 风格
- 具体可执行：写清责任角色、时限（工作日）、数值阈值、金额/比例、示例场景。
- 不写空话套话；不出现"AI""示例公司""（略）""待补充"等字样；不出现真实企业名。
- 术语首次出现给英文缩写。

## 硬性规则（违反会导致返工）
- 你的全部工作只有一次工具调用：调用一次 write 写文件。
- 禁止调用 bash/edit/read/glob/grep；禁止统计汉字个数；禁止回读或修改已写文件。
- write 的 content 参数里直接放完整正文，一次写全，写完立即结束。
- 长度按你的估计控制即可，宁可略短也不要回改。

## 交付
用 write 把正文写入：<绝对路径>/ch<NN>.md
写完后只回复一行：`OK ch<NN>`。不要回复正文。
```

每一段为什么存在：

- **覆盖内容 / 边界**：防止并行单元之间内容重叠，这是套话和重复的主要来源。
- **格式**：首行与标题层级固定下来，拼装和目录生成才能机械化。
- **篇幅 + 硬性规则**：唯一能挡住"写→数→改"循环的约束。必须显式禁止工具，含糊地说"别反复改"没有用。
- **交付 + 一行确认**：Agent 最后一条消息保持极短，编排层就不必承载正文。

## 附录单元

骨架相同，首行换成 `## 附录 X ...`，正文要求换成可枚举的产物：

```
## 内容
收录 <80> 个<条目>，用一张 Markdown 表格呈现，列：<列名>。每行释义 15～40 字。
```

附录比正文更适合用脚本生成而不是 Agent：常见问题、术语表、表单清单、联系表、修订记录、参数表都属于这一类。

## 扩写补充（只做一次，仅用于偏短的单元）

```
你之前生成的 <路径> 只有 <X> 个汉字，目标是 6,000。
请只做一次 edit：在章节末尾追加 1～2 个小节，补充 <具体角度>，使总长度接近 6,000 个汉字。
不要重写已有内容，不要统计字数，不要多次修改。完成后只回复 `OK`。
```

一次扩写还不够，就整章重新生成——比第二次循环便宜。

## 编排层要点

这些是写给编排者的，不是写给每个章节 Agent 的：

- 单元清单：id、标题、覆盖主题、边界、输出路径
- 每批不超过 6 个
- 每批结束后检查每个输出文件是否存在
- 文件缺失时只重生成那一个单元，不要整批重来
- 不要为了改并发数而重启；批次大小一次定好
